Kleinen TLS-MQTT-Server für TeddyCloud einrichten

Diese Anleitung installiert Mosquitto als dauerhaften MQTT-Broker:

  • TLS auf Port 1883
  • Benutzername und Passwort
  • keine Traffic-Logs
  • persistente Retained Messages und MQTT-Sitzungen
  • verwendbar durch TeddyCloud und Android-Apps
Vorbereitung: Die neutrale Beispieladresse 192.168.1.100 muss durch die tatsächliche IP des eigenen Docker-Hosts ersetzt werden.

1. Verzeichnisse anlegen

cd /home/teddycloud/teddycloud-yml
sudo mkdir -p mosquitto/certs
sudo nano mosquitto/mosquitto.conf

2. Mosquitto konfigurieren

Inhalt von mosquitto/mosquitto.conf:

listener 1883 0.0.0.0
protocol mqtt

allow_anonymous false
password_file /mosquitto/config/passwords

certfile /mosquitto/certs/server.crt
keyfile /mosquitto/certs/server.key
require_certificate false

persistence true
persistence_location /mosquitto/data/
persistence_file mosquitto.db

log_dest none
connection_messages false

3. MQTT-Benutzer erzeugen

cd /home/teddycloud/teddycloud-yml
sudo touch mosquitto/passwords

sudo docker run --rm -it \
  --user 0:0 \
  --entrypoint mosquitto_passwd \
  -v "$PWD/mosquitto:/mosquitto/config" \
  eclipse-mosquitto:2.1.2-alpine \
  -c /mosquitto/config/passwords teddycloud

teddycloud ist der frei wählbare MQTT-Benutzername. Das Passwort wird interaktiv abgefragt.

4. TLS-Zertifikate erzeugen

cd /home/teddycloud/teddycloud-yml

sudo openssl req \
  -x509 -newkey rsa:4096 -nodes -sha256 -days 3650 \
  -subj "/CN=Local MQTT CA" \
  -keyout mosquitto/certs/ca.key \
  -out mosquitto/certs/ca.crt

sudo openssl req \
  -new -newkey rsa:2048 -nodes -sha256 \
  -subj "/CN=mosquitto" \
  -keyout mosquitto/certs/server.key \
  -out mosquitto/certs/server.csr

sudo tee mosquitto/certs/server.ext >/dev/null <<'EOF'
basicConstraints=critical,CA:FALSE
keyUsage=critical,digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth
subjectAltName=DNS:mosquitto,IP:192.168.1.100
EOF

sudo openssl x509 \
  -req -sha256 -days 825 \
  -in mosquitto/certs/server.csr \
  -CA mosquitto/certs/ca.crt \
  -CAkey mosquitto/certs/ca.key \
  -CAcreateserial \
  -extfile mosquitto/certs/server.ext \
  -out mosquitto/certs/server.crt

sudo rm mosquitto/certs/server.csr mosquitto/certs/server.ext

sudo chown 1883:1883 \
  mosquitto/passwords \
  mosquitto/certs/server.key \
  mosquitto/certs/server.crt

sudo chmod 600 \
  mosquitto/passwords \
  mosquitto/certs/server.key \
  mosquitto/certs/ca.key

sudo chmod 644 \
  mosquitto/mosquitto.conf \
  mosquitto/certs/server.crt \
  mosquitto/certs/ca.crt

5. Compose ergänzen

In docker-compose.github.yaml ergänzen. Port 1883 darf nur bei Mosquitto veröffentlicht werden:

services:
  teddycloud:
    volumes:
      - ./mosquitto/certs/ca.crt:/teddycloud/config/mosquitto-ca.crt:ro

  mosquitto:
    image: eclipse-mosquitto:2.1.2-alpine
    container_name: mosquitto
    restart: unless-stopped
    ports:
      - "1883:1883"
    volumes:
      - ./mosquitto/mosquitto.conf:/mosquitto/config/mosquitto.conf:ro
      - ./mosquitto/passwords:/mosquitto/config/passwords:ro
      - ./mosquitto/certs/server.crt:/mosquitto/certs/server.crt:ro
      - ./mosquitto/certs/server.key:/mosquitto/certs/server.key:ro
      - mosquitto_data:/mosquitto/data

volumes:
  mosquitto_data:

6. Broker starten

cd /home/teddycloud/teddycloud-yml

PROJECT="$(sudo docker inspect -f '{{ index .Config.Labels "com.docker.compose.project" }}' teddycloud)"

sudo docker compose \
  -p "$PROJECT" \
  -f docker-compose.yaml \
  -f docker-compose.github.yaml \
  up -d --no-deps mosquitto

sudo docker port mosquitto

Erwartet:

1883/tcp -> 0.0.0.0:1883

FeldWert

Port1883
TLS/SSLEIN

Passwortzuvor vergebenes Passwort
CA-Zertifikatca.crt

Die CA-Datei liegt unter:

/home/teddycloud/teddycloud-yml/mosquitto/certs/ca.crt
TeddyRemote: Die aktuelle App bestätigt beim Verbindungstest den SHA-256-Fingerprint des unbekannten Brokerzertifikats und speichert diesen im Profil. Android-Clients mit CA-Import verwenden stattdessen die oben genannte ca.crt.

Für TeddyCloud-Nachrichten kann die App anschließend dieses Topic abonnieren:

teddyCloud/#
Sicherheit: Port 1883 verwendet in diesem Aufbau TLS. Den Broker nicht ungeschützt ins Internet veröffentlichen.
